# אפיון שאלון דיגיטלי — "מפה אישית: ראש, לב, בטן בניהול שלך"

מסמך אפיון למפתח. מתאר את מבנה השאלון, חוויית המשתמש, מודל הנתונים, לוגיקת הערבול (shuffling), ולוגיקת הניקוד והפלט.

---

## 1. רקע ומטרה

כלי רפלקציה אישי לסדנת ניהול. המשתמש מדרג 18 היגדים בסולם 1–5. מאחורי הקלעים כל היגד משויך לאחד משלושה "מרכזים ניהוליים" — **ראש**, **לב**, **בטן** — והמערכת מחשבת ציון נפרד לכל מרכז ומציגה פלט אישי.

**הכלי אינו שאלון אבחוני מתוקף מחקרית.** מטרתו לעורר מחשבה, לספק אינדיקציה ראשונית לנטיות ניהוליות, ולשמש עוגן לשיח ולרפלקציה בסדנה.

---

## 2. עקרון מנחה קריטי — החלוקה לקטגוריות מוסתרת מהמשתמש

> זוהי הדרישה המרכזית של השאלון. יש לוודא שהיא מיושמת במלואה.

- המשתמש **לא רואה** את החלוקה לראש / לב / בטן ולא רואה כותרות קטגוריה.
- המשתמש רואה רשימה אחת רציפה של 18 היגדים, **בסדר אקראי**, כל אחד עם סולם 1–5.
- השיוך של כל היגד לקטגוריה הוא **נתון backend בלבד** ומשמש אך ורק לחישוב הציונים והפלט.
- אין צורך בשום חלוקה ויזואלית, מספור לפי קטגוריה, או רמז שמתקיימת חלוקה כלשהי.

---

## 3. חוויית המשתמש (Frontend)

### 3.1 מסך פתיחה

טקסט שמוצג למשתמש לפני תחילת השאלון:

> מנהיגות אפקטיבית בעולם המודרני משלבת בין ניתוח רציונלי, חיבור אנושי ואומץ ניהולי.
> שאלון זה נועד לעזור לך לזהות את הנטיות הניהוליות הדומיננטיות אצלך כיום, ואת האזורים שבהם כדאי להשקיע מאמץ מודע לפיתוח ולאיזון.
>
> *הכלי אינו שאלון אבחוני מתוקף מחקרית. מטרתו לעורר מחשבה ולשמש עוגן אישי לשיח, ללמידה ולרפלקציה במהלך הסדנה.*

### 3.2 הסבר סרגל הדירוג

יש להציג למשתמש את משמעות הציונים (טקסט קבוע, לא חלק מהערבול):

| ציון | משמעות |
|------|---------|
| 1 | כמעט אף פעם לא |
| 2 | לעיתים רחוקות |
| 3 | לפעמים |
| 4 | לעיתים קרובות |
| 5 | כמעט תמיד |

הנחיה למשתמש: "דרג/י כל היגד לפי מידת התאמתו להתנהגותך **בפועל**."

### 3.3 הצגת ההיגדים

- 18 היגדים, סדר אקראי (ראו סעיף 5).
- כל היגד מוצג עם בורר 1–5 (radio / סקאלה).
- RTL מלא, פונט עברי.
- ללא כותרות קטגוריה וללא קיבוץ.
- מומלץ: כל ההיגדים חובה למענה לפני סיום (אחרת לא ניתן לחשב ציון מלא — ראו 6.4).

## 4. מאגר ההיגדים — מיפוי backend (לעיני המפתח בלבד)

כל היגד מקבל `id` קבוע ושיוך `category` קבוע. **שדה ה-`category` לא נשלח ל-Frontend ולא מוצג למשתמש.** הוא משמש רק לחישוב.

קידוד הקטגוריות: `head` (ראש), `heart` (לב), `gut` (בטן).

### קטגוריה: head (ראש — אינטליגנציה קוגניטיבית ואנליטית)

| id | היגד |
|----|------|
| h1 | אני מצליח/ה לראות את התמונה הרחבה והאסטרטגית, ולא רק את המשימה המיידית |
| h2 | אני מקבל/ת החלטות ניהוליות על בסיס נתונים, עובדות וניתוח מסודר |
| h3 | אני יודע/ת לתעדף ביעילות בין משימות מתחרות, גם תחת לחץ זמנים |
| h4 | אני מזהה דפוסים, מגמות וסיכונים עתידיים לפני שהם הופכים לבעיה בשטח |
| h5 | אני יודע/ת לפרק אתגרים ובעיות מורכבות לחלקים פשוטים שניתן לטפל בהם |
| h6 | אני שואל/ת שאלות שמחדדות חשיבה ומעודדות העמקה, ולא רק מגיב/ה למה שקורה |

### קטגוריה: heart (לב — אינטליגנציה רגשית ומנהיגות אנושית)

| id | היגד |
|----|------|
| e1 | אני מזהה מתי חבר או חברת צוות נמצאים במצוקה, גם אם דבר לא נאמר לי במפורש |
| e2 | אנשים סביבי מרגישים בנוח לשתף אותי בקשיים, בחששות או באי-הסכמות |
| e3 | אני מקשיב/ה באמת ובסבלנות לאחרים, ולא רק ממתין/ה לתורי לדבר |
| e4 | אני יודע/ת לנהל שיחות מורכבות וקשות מבלי להיכנס למגננה או למתקפה אישית |
| e5 | אני מודע/ת להשפעה הרגשית ולהשלכות של מצב הרוח וההתנהגות שלי על הסובבים אותי |
| e6 | אני מצליח/ה לחבר אנשים למשמעות ולמוטיבציה פנימית, ולא רק לחלק להם משימות יבשות |

### קטגוריה: gut (בטן — אינטואיציה, אומץ ונוכחות מנהיגותית)

| id | היגד |
|----|------|
| g1 | אני מסוגל/ת לקבל החלטות אמיצות ולהתקדם גם כאשר המידע שברשותי חלקי ביותר |
| g2 | אני סומכ/ת על האינטואיציה ותחושות הבטן המקצועיות שלי לצד בחינת הנתונים היבשים |
| g3 | אני לא נמנע/ת משיחות קשות, מהצבת גבולות ברורים או מקבלת החלטות לא פופולריות |
| g4 | אני שומר/ת על יציבות ורוגע פנימי גם כשהסביבה שלי כאוטית, לחוצה ולא ודאית |
| g5 | אני מוכן/ה לקחת סיכונים מחושבים ולשלם מחיר אישי מסוים כדי לקדם שינויים נחוצים |
| g6 | אני קשוב/ה לתחושות הפיזיות של הגוף שלי (כיווץ, מתח, שקט) ולא מתעלם/ת מהן בקבלת החלטות |

## 5. ערבול (Shuffling)

- כל 18 ההיגדים מוצגים ברצף אחד מעורבל.
- הערבול הוא ברמת ההיגד הבודד — אין לשמור על רצפים פנימיים של קטגוריה.
- שתי גישות אפשריות, לבחירת המפתח:
  - **ערבול אקראי לכל משתמש (מומלץ):** מערבלים את המערך בכל טעינה. ה-`id` נשמר עם כל תשובה כך שהשיוך לקטגוריה אינו תלוי בסדר התצוגה.
  - **סדר מעורבל קבוע מראש:** סדר אחיד שנקבע פעם אחת ומשותף לכל המשתמשים (פשוט יותר לניתוח השוואתי, אם יידרש).
- בשני המקרים: התשובה נשמרת לפי `id` ההיגד, ולא לפי מיקומו בתצוגה.

## 6. לוגיקת ניקוד (Backend)

### 6.1 איסוף תשובות

לכל היגד נשמר ערך 1–5. מבנה לדוגמה:

```json
{
  "responses": {
    "h1": 4, "h2": 5, "h3": 3, "h4": 4, "h5": 2, "h6": 4,
    "e1": 3, "e2": 4, "e3": 5, "e4": 3, "e5": 4, "e6": 4,
    "g1": 2, "g2": 3, "g3": 4, "g4": 3, "g5": 2, "g6": 3
  }
}
```

### 6.2 חישוב ציון לכל מרכז

לכל קטגוריה — סכום 6 ההיגדים שלה.

- טווח אפשרי לכל מרכז: **6 (מינימום) עד 30 (מקסימום)**.
- `head_score = h1 + h2 + h3 + h4 + h5 + h6`
- `heart_score = e1 + e2 + e3 + e4 + e5 + e6`
- `gut_score = g1 + g2 + g3 + g4 + g5 + g6`

### 6.3 סיווג רמת דומיננטיות לכל מרכז

| רמה | טווח ניקוד |
|------|------------|
| נמוך | 6–14 |
| בינוני | 15–22 |
| גבוה | 23–30 |

### 6.4 מקרי קצה

- אם חסרות תשובות — לחסום סיום עד מענה מלא (מומלץ), או לא לחשב ציון חלקי.
- ניתן גם לזהות את **המרכז הדומיננטי** (הציון הגבוה מבין השלושה) ואת **המרכז לפיתוח** (הנמוך), לצורך הפלט.

---

## 7. פלט למשתמש

לאחר הסיום מציגים למשתמש את שלושת הציונים והרמות, ללא חשיפת ה"נוסחה" שמאחורי הקלעים. הצעה למבנה:

- ציון ורמה לכל מרכז (ראש / לב / בטן).
- הדגשת המרכז הדומיננטי והמרכז שכדאי לפתח.
- טקסט מלווה קצר לכל מרכז (תוכן ינוסח בנפרד ע"י צוות התוכן).

> בשלב הפלט מותר וגם רצוי להשתמש בשמות "ראש / לב / בטן" — ההסתרה נדרשת רק במהלך מענה השאלון, לא בתוצאות.

---

## נספח: הערות המקור מהמסמך (לעיני המפתח — לא חלק מהשאלון)

ההערות הבאות שולבו במסמך המקור לצורך קונטקסט והובהרו לכלל הדרישות שלמעלה. אינן מוצגות למשתמש:

- כותרות הקטגוריות ("חלק א': הראש", "חלק ב': הלב", "חלק ג': הבטן") נכתבו לצורך הבנה בלבד — בפועל יש לעשות shuffling בין כל השאלות, והאפליקציה היא זו שמשייכת כל היגד לקטגוריה הנכונה מאחורי הקלעים, מסכמת תוצאות ומפיקה פלט.
- לא יופיעו כותרות "ראש" / "לב" / "בטן" בשאלון. השאלון מורכב מהסבר למשתמש + היגדים עם סולם בחירה בלבד.
- ניקוד: 6 היגדים לכל סוג, מקסימום 30, מינימום 6.
